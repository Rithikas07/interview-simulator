AN INTERACTIVE JAVA TECHNICAL REVIEW SIMULATOR Java AI Interview Simulator — an offline-capable, core-Java mock-interview and placement-readiness tool
ABSTRACT

A console-based placement-preparation application, built entirely in core Java, that helps engineering students rehearse core-Java technical interviews. It loads a 23-question bank across six topics from JSON (Gson), sets questions via a Random, Balanced or Topic-focused strategy, and scores each typed answer through a pluggable evaluator chain (Claude, Gemini, Ollama) that falls back to an offline keyword evaluator. Every session ends with a topic-wise placement-readiness report, and a 34-test JUnit 5 suite passes at 100%.

INTRODUCTION

Campus placement drives almost always include a core-Java technical round on OOP, Collections, exceptions, the JVM and multithreading — yet most students practise only with static notes or written quizzes, with no interactive tool that gives instant, keyword-level feedback. This project treats interview preparation as a well-scoped software-engineering problem: an offline, no-cost Java simulator with topic-wise diagnostic feedback. Because it is written with the very concepts it tests, building it also reinforces the subject.

OBJECTIVES
  1. Design a question-bank schema and load it from an external JSON file.
  2. Model the system with OOP classes and interfaces for question selection and answer evaluation.
  3. Implement offline keyword scoring, with an optional AI-backed evaluator behind the same interface.
  4. Run a topic-focused mock interview and report placement readiness — no network or paid service needed.
  5. Verify the core logic with an automated JUnit 5 test suite.

DISCUSSION
  • 34/34 passing tests confirm the model, evaluator and question-setter logic — including the FallbackEvaluator's exception path.
  • Keyword scoring rewards exact technical vocabulary (100% on Collections and JVM).
  • Limitation: correct but differently-phrased answers can score poorly — Exceptions scored 0% when the drawn question was on try-with-resources.
  • AI evaluators were built to address this but were not exercised (no API key or local Ollama).
CONCLUSION
  • Answers the driving question: an offline-capable console tool that runs a realistic core-Java mock interview.
  • JSON question bank, three interchangeable question setters and a resilient evaluator chain.
  • 34/34 JUnit tests and an end-to-end demo (73%, "ALMOST THERE") confirm it works as designed.
  • Hands-on practice with interfaces, inheritance, collections, exceptions and Strategy / Factory / Decorator patterns.
FUTURE ENHANCEMENTS
  • Semantic / embedding-based scoring for correct but keyword-light answers.
  • Persistent storage (file or database) so candidate history survives restarts.
  • Larger question bank with validated, user-contributed questions.
  • A GUI or web front-end on top of the existing UI-agnostic service layer.
  • Test the Claude / Gemini / Ollama evaluators end-to-end with API access.
